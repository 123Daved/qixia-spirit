# 部署与功能边界

## 当前部署

- 前端入口：https://123daved.github.io/qixia-spirit/
- GitHub 仓库：`123Daved/qixia-spirit`，Pages 从 `main` 根目录发布。
- 云端 API：https://qixia-spirit-api-123daved.sharp-tapir-4242.chatgpt.site
- 云端源码：`cloud-backend/`，Sites 项目配置在其 `.openai/hosting.json`。
- 本机 Node 服务：`node server.mjs`，当前本机配置监听 `127.0.0.1:8790`。

GitHub Pages 本身不运行后端。`assets/cloud-api.js` 仅在本仓库的正式 Pages 路径启用，将 `/api/*` 请求发送至云端。其他素材仍来自 GitHub。主页面和嵌入的沙盘均加载同一转发脚本。localhost 继续使用本地 Node 服务；`?demo=1` 在 GitHub 上保留原静态演示（旧浏览器来信也仍留在该模式）。本机 Node 服务会将旧的 demo 参数重定向至真实功能模式。

## 真实能力

- 自由对话、图片理解、语音：服务端调用已有兼容模型 API，保留流式输出。
- 个人行记：D1 持久化，浏览器个人凭证的哈希控制读取和删除权限。不会上传本地旧数据库或自动迁移旧的浏览器来信；不同浏览器/域名的个人凭证不同，没有正式账号恢复或跨设备同步。
- 公开来信：提交进入待审核状态，不会直接公开。匿名公网不开放管理员审核入口。
- 海报：上传、任务状态、模型生成、结果取回和本地排版下载。R2 保存输入及结果；输入在生成结束后删除，结果约 30 分钟后无法取回。过期任务随后续海报请求分批清理。未领取的任务也通过此清理机制移除。
- 观光车与客流：继续为示意/估算。司机上报和审核工具只保留在受保护的本地环境，不作为匿名写接口公开。

## 密钥与额度

模型凭据通过 Sites 运行时秘密变量配置：`QIXIA_API_KEY`、`QIXIA_API_BASE`；模型选择变量为 `VISION_MODEL`、`TTS_MODEL`、`IMAGE_MODEL`（可选）。源码和前端只记录后端 URL，不包含模型密钥。更改云端变量后需要重新部署已保存的版本。

云端限制：每个来源 IP 每 10 分钟 120 次 POST；海报每 IP 每小时 5 次、全站每天 40 次；其他 AI 调用全站每天 1500 次。超限显示可重试的错误。这些限制是当前体验环境的配额，模型调用仍使用账户本身的额度，免费前端托管不代表模型免费。

CORS 仅允许正式 GitHub 页面来源和后端自身来源。私人记录按个人凭证校验；CORS 不是身份验证机制。生产运营仍需要完善账户、监控、审核运营和数据保留策略。

## 发布维护

1. GitHub 前端：检查 `git diff` 和秘密文件排除后提交并推送 `main`，等待 Pages 构建成功。
2. 云端后端：使用 Sites 技能，从对应项目源码更新 `backend/` 和 `db/schema.ts`。结构变更运行 `npm run db:generate`，保留已应用迁移不变；构建、同步源码、打包、保存并部署。
3. 后端必须先通过线上 API 测试，再更新前端地址；不要把密钥添加到 HTML 或 `cloud-api.js`。
4. 仓库中的后端源码是部署版本的副本；本机 Sites 工作目录为独立仓库。修改副本后需同步至对应 Sites 源仓库并发布，单独推送 GitHub 不会自动更新 Sites。

## 验证范围与网络

已对云端进行真实对话、识图、语音、来信保存读取和权限隔离测试。海报生成和 GitHub 发布状态以本次发布完成记录为准。自动化回归覆盖八景海报入口和上传弹窗、三种视图切换与后端权限。
