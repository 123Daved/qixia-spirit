# 部署与功能边界

## 1. 免费演示：GitHub Pages

- 仓库：`123Daved/qixia-spirit`。
- 发布源：`main` 分支根目录。
- 首页：`index.html`；`.nojekyll` 确保静态资源按原路径提供。
- 入口与本地资源采用相对路径，兼容 `/qixia-spirit/` 项目路径。
- GitHub Pages 不运行 `server.mjs`，因此公开站点加载 `assets/demo-mode.js`，将来信存储在浏览器，并为服务器专属功能返回清晰的演示说明。
- 旧沙盘的配套资源在 `legacy-sandbox/`，不要只上传 HTML 或删除该目录。

## 2. 完整后端部署

建议使用支持 Node.js 22.16+ 与持久化磁盘的服务器。`server.mjs` 提供页面、模型代理、SQLite 来信、车辆位置和海报接口。以 `.env.example` 为模板配置环境；不得将密钥写入浏览器文件。

需要配置并验证：兼容模型地址、文本/视觉/语音/图片模型、持久化数据库、HTTPS、反向代理、访问控制、接口额度与审核流程。当前 demo 中的司机和审核工具属于原型，不能未经访问控制直接作为正式管理后台公开运行。

当前公开版仅运行静态文件。若迁移完整后端到公网，移除两个页面中的 `assets/demo-mode.js` 引用，并恢复 `letters.js` 中适用于服务端存储的文案，然后验证真实保存、权限、公开审核、删除与跨设备读取。

## 3. 国内访问

GitHub Pages 提供免费公开链接，但不能据此承诺国内所有网络均无需代理、稳定直连。若有面向国内游客的稳定访问需求，可将同一静态目录部署至国内或香港托管，并绑定自有域名。具体域名、备案与费用条件取决于服务商和部署地区，需在选择服务时确认。

官方参考：
- [GitHub Pages 静态托管说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- [阿里云 OSS 静态网站托管](https://help.aliyun.com/zh/oss/user-guide/hosting-static-websites)

## 4. 发布前检查

1. 首页默认画卷；3D按钮进入旧沙盘；底部“山境画卷”可以返回。
2. 四张服务卡片位于下方，景点故事可打开关闭。
3. 页面没有直接引用 `file://`、本机绝对路径或凭据文件。
4. 个人行记明确标注本机存储，公开发布不能假装成功。
5. 检查浏览器控制台与资源路径，保存截图。
6. 发布后检查首页和关键资源，记录实际验证范围；未做国内多运营商测试时不声称通过。

## 5. 不随源码发布的数据

`.env.local`、`certs/`、`.data/`、浏览器的本地行记以及用户对话均未上传。公共演示产生的新行记只在访问者当前浏览器中保存。
